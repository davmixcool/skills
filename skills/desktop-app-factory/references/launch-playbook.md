# Desktop App Factory — Launch Playbook

## Stage 1 — Validate the annoyance

Before building deeply, answer:
- who experiences this?
- how often?
- what do they do today?
- what does it cost in time/money/attention?
- why does desktop access make the solution better?

Create a 5–10 second demo/hook before a feature roadmap.

## Stage 2 — Build the smallest complete loop

Ship only what is needed for:

`trigger -> action -> result`

Examples:
- hotkey -> capture -> saved queue item
- watched folder event -> organize file -> undo/history
- clipboard action -> transformed output -> paste/copy

## Stage 3 — Dogfood hard

Desktop utilities reveal edge cases through real daily use.

Test:
- cold start
- app already running
- restart/reboot
- permission revoked
- path moved/deleted
- shortcut conflict
- multiple monitors
- network unavailable
- updater unavailable

## Stage 4 — Package and release

Prepare:
- landing page
- short demo video/GIF
- signed installers/packages
- privacy policy if needed
- pricing/trial/license flow
- crash/error reporting
- update path

## Stage 5 — Acquire users

Good channels depend on audience:
- developer communities/GitHub/Hacker News for dev tools
- Product Hunt for demo-friendly utilities
- Reddit communities where the pain is discussed
- YouTube/TikTok/X for visual before/after workflows
- SEO for “how to…” utility pain
- App stores where discovery matches the product
- targeted communities/newsletters

Do not spray every launch channel. Pick where the exact user already complains.

## Stage 6 — Measure real value

Look for:
- first-success rate
- repeated successful actions
- retained installations
- conversion to paid
- support burden
- failure rate
- acquisition source quality

## Stage 7 — Decide

### Kill
Pain is weak or acquisition/payment signals fail.

### Maintain
Small paid utility with low support load.

### Grow
Strong repeat use plus a workable acquisition path.

### Graduate
The utility has become a wedge into a deeper workflow customers want you to own.

Do not turn every successful utility into SaaS. A durable small paid app can be the correct outcome.
